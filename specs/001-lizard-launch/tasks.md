## M0 — 프로토타입: "발사가 된다" (핵심 손맛 검증)
> 목표: 못생겨도 좋으니 **충전→발사→비거리**가 손맛 있게 동작. 여기서 재미 없으면 방향 수정.

- ☑ `[P1]` T0.1 프로젝트 셋업 (Godot 4 프로젝트·메인 씬·1280×720) *(plan §1)*
- ☑ `[P1]` T0.2 입력 추상화: 탭/스페이스/클릭/터치 → "탭" 액션 *(US-6, plan §2.2)*
- ☑ `[P1]` T0.3 파워 게이지: 연타 충전 + 자연 감소 + 3초 타이머 + 오버차지 *(US-1, GDD §4.1)*
- ☑ `[P1]` T0.4 발사 공식 구현 `LaunchFormula.gd` (오버차지·각도·바운스 포함) *(contracts)*
- ☑ `[P1]` T0.5 비행 렌더: 포물선 연출 + 도마뱀(도형 임시) + 비거리 표시 *(US-1)*
- ☑ `[P1]` T0.6 상태머신: READY→CHARGE→AIM→FLIGHT→RESULT→다시하기 *(plan §2.1)*
- ◐ `[P2]` T0.7 **플레이 검증 회고**: 손맛 OK? 제한시간/증가량 튜닝 *(GDD §9)* — *Godot 실행 검증 대기*

> 참고: M0에 본래 M1 예정이던 **각도 단계(AIM)** 까지 선반영함(확정된 2단계 발사 시연 목적).
> T1.1/T1.2 일부가 함께 구현됨. 발사 공식 불변식 A~F는 별도 검증 통과(Python 포팅 대조).

**M0 완료 정의:** 키 하나로 충전→발사→비거리 확인→다시하기가 10초 내 반복된다.
**남은 것:** Godot 4 에디터에서 실제 실행·손맛 검증(T0.7), 저장(T1.5).

## M1 — 코어 루프: 실력이 반영된다
> 목표: 각도/타이밍 도입, 결과 화면, 저장. "잘하면 더 멀리"가 체감된다.

- ☐ `[P1]` T1.1 각도 게이지: 왕복 바늘 + 스위트스팟 + 확정 입력 *(US-2, GDD §4.1)*
- ☐ `[P1]` T1.2 발사 공식에 `sweet`·`angle` 결합, 퍼펙트 판정 *(contracts §3)*
- ☐ `[P1]` T1.3 발사 공식 단위 테스트(불변식 A~F) *(contracts §4, Vitest)*
- ☑ `[P1]` T1.4 결과 화면: 비거리/퍼펙트/획득 에너지/신기록 *(US-4, GDD §7.2)*
- ☑ `[P1]` T1.5 저장: 최고기록·누적 에너지 `user://save.json` (`SaveData.gd`) *(US-4, plan §2.3)*
- ☐ `[P2]` T1.6 오버차지 구간 + 위험/보상 밸런싱 *(GDD §9)*
- ☐ `[P2]` T1.7 효과음 1차(연타·발사·퍼펙트·착지) *(US-8)*

**M1 완료 정의:** 같은 사람이 연습하면 기록이 늘고, 기록이 저장된다.

## M2 — 진화: 성장 보상
> 목표: 도마뱀→모토마→미라이돈 진화와 능력치 상승, 진화 연출.

- ☐ `[P1]` T2.1 진화 단계·능력치 테이블 `evolution.ts` *(GDD §3.3)*
- ☐ `[P1]` T2.2 누적 에너지 임계값 도달 시 진화 트리거 *(US-3, GDD §3.2)*
- ☐ `[P1]` T2.3 진화별 스프라이트 3종 + HUD 진화 표시(●●○) *(GDD §3.1, §7.1)*
- ☑ `[P1]` T2.4 진화 연출(점멸+확대 펄스 + EVOLVED 배너) + 탭 스킵 *(GDD §3.4)*
- ☐ `[P2]` T2.5 능력치 변화가 공식에 반영됨을 테스트(불변식 D) *(contracts)* — *Python 대조 검증 완료, GDScript 단위테스트 미작성*

**M2 완료 정의:** 반복 플레이로 진화하며, 진화 후 눈에 띄게 더 멀리 난다. ✅
> 추가: 사운드(`AudioManager.gd`, 절차적 합성)로 T1.7/US-8 효과음도 함께 구현.

## M3 — 2인 대결: 같이 논다
> 목표: 로컬 턴제 대결(베스트 오브 3)과 리매치. 입력 분리.

- ☑ `[P1]` T3.1 세션/턴 관리 (Main.gd 상태머신 내 P1→P2→비교) *(US-5, plan §2.1)*
- ☑ `[P1]` T3.2 입력 키 분리(P1 `A` / P2 `L`) + 화면 좌/우 영역 분리(터치) *(US-5,6)*
- ☑ `[P1]` T3.3 대결 결과: 양측 비거리·승자·스코어(3판 2선승) *(US-5, GDD §7.2)*
- ☑ `[P1]` T3.4 리매치 흐름(매치 종료→즉시 재대결 / Esc 타이틀) *(US-5)*
- ☐ `[P2]` T3.5 핸디캡 옵션(진화 격차 보정) *(GDD §5.2)* — *미구현(현재 양측 동일 단계)*

**M3 완료 정의:** 두 명이 같은 기기에서 충돌 없이 대결하고 즉시 리매치한다. ✅
> 참고: 턴 관리는 별도 `Session` 파일 대신 Main.gd 상태머신에 통합(프로토타입 단순화).
> 대결은 일회성 듀얼이라 저장에 영향 없음(양측 동일 진화 단계로 공정). 동시 분할화면은 추후(M3 확장).

## M4 — 살붙이기: 콘텐츠 & 폴리시
> 목표: 스토리 지역, 상점, 스킨, 사운드/연출 완성도.

- ◐ `[P2]` T4.1 스토리 4개 지역 + 해금(누적 비거리) + 바람 (`Region.gd`) *(GDD §2.3)* — *상승기류 발판 미구현*
- ◐ `[P2]` T4.2 상점: 영구강화(가벼운 비늘·강화 코어) + 지갑/누적 분리 *(US-7, GDD §6)* — *부스터·스킨 미구현*
- ☐ `[P2]` T4.3 무한 챌린지 + 로컬 리더보드 *(GDD §5.1)*
- ☐ `[P3]` T4.4 일일 도전(시드 고정) *(GDD §5.1, plan §2.4)*
- ☐ `[P3]` T4.5 배경 패럴랙스·진화 이펙트·BGM(오리지널 자산) *(GDD §8)*
- ☐ `[P3]` T4.6 접근성(색맹 무늬 표기, 언어 토글) *(GDD §7.3)*

**M4 완료 정의:** 처음~엔딩까지 플레이 가능하고, 꾸미기·도전 욕구가 생긴다.
> 진척: 지역(바람·하늘색 변화)·상점(영구강화) 핵심부 구현. 무한챌린지·스킨·일일도전·BGM은 잔여.

## 작업 진행 규칙
1. **위에서 아래로.** M0이 검증되기 전에는 M1로 넘어가지 않는다(원칙 8).
2. **공식 변경은 문서부터.** 밸런싱 수치 변경은 `contracts` / `game-design.md` 갱신 후 코드 반영.
3. **순수 로직은 테스트 동반.** `core/*`는 Vitest 없이 머지하지 않는다(plan §2.3).
4. **플레이 검증.** 각 마일스톤 끝에 실제로 플레이하고 회고를 남긴다.
