# 프로젝트 헌장 (Constitution) — 도마뱀 발사!

> 이 문서는 프로젝트가 **절대 어기지 않을 핵심 원칙**을 정의합니다.
> 모든 명세·설계·구현 결정은 아래 원칙과 충돌하면 안 됩니다.
> 원칙을 바꾸려면 이 문서를 먼저 개정하고 합의해야 합니다.

- **버전:** 0.1.0 (초안)
- **최종 수정일:** 2026-06-27

## 원칙 1. "한 번의 발사"가 재미의 핵심이다
게임의 모든 것은 *게이지를 채우고 → 발사하고 → 멀리 날아가는* 한 사이클에 집중한다.
이 사이클이 **3초 안에 손맛**을 줘야 하며, 어떤 신규 기능도 이 핵심 루프를
복잡하게 만들어서는 안 된다. 의심스러우면 핵심 루프를 보호하는 쪽을 택한다.

## 원칙 2. 누구나 10초 안에 이해한다
첫 플레이어가 **튜토리얼 없이 10초 안에** 조작을 이해할 수 있어야 한다.
조작은 최소화한다(기본 1~2개 입력). 설명이 필요하면 디자인이 잘못된 것이다.

## 원칙 3. 혼자도, 둘이도 똑같이 재미있다
싱글 플레이와 2인 플레이는 **동등한 1급 시민**이다.
한쪽을 위해 다른 쪽의 재미를 희생하지 않는다. 핵심 발사 로직은
플레이어 수와 무관하게 **동일한 규칙**으로 동작한다.

## 원칙 4. 진화는 보상이지 장벽이 아니다
도마뱀 → 모토마 → 미라이돈으로의 진화는 **성취의 보상**이다.
진화하지 못해도 게임을 즐길 수 있어야 하며, 진화는 능력치 상승과
시각적 쾌감을 주되 **운(運)이 아니라 실력/반복**으로 도달 가능해야 한다.

## 원칙 5. 입력 지연 0을 사수한다 (반응성 우선)
타이밍 게임의 생명은 **입력 반응성**이다. 입력에서 화면 반영까지의 지연은
실기준 1~2 프레임을 넘지 않는다. 화려한 연출보다 **반응성이 항상 우선**한다.

## 원칙 6. 오리지널 자산으로 만든다 (IP 안전)
"모토마/미라이돈" 등은 기존 IP를 연상시키므로, 실제 구현 자산
(이름·외형·기술명·BGM)은 **자체 제작 오리지널**로 만든다.
기획 단계의 레퍼런스로만 해당 콘셉트를 사용하고, 배포물에는
타사 IP 자산을 포함하지 않는다. (코드네임은 기획용으로만 사용)

## 원칙 7. 명세가 먼저, 코드가 나중 (SDD)
새로운 기능은 반드시 `spec.md`(무엇/왜) → `plan.md`(어떻게) →
`tasks.md`(작업) 순으로 문서화한 뒤 구현한다.
명세 없는 코드는 머지하지 않는다.

## 원칙 8. 작게 만들어 자주 검증한다
거대한 완성본을 한 번에 만들지 않는다. **플레이 가능한 최소 버전(MVP)**을
먼저 만들고, 실제로 손맛을 검증한 뒤 살을 붙인다.
